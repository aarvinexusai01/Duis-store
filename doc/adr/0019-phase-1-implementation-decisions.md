# ADR-0019: Phase 1 implementation decisions

- Status: Accepted
- Date: 2026-10-15
- Deciders: Engineering (Phase 1), checked against the installed packages and the Next.js 16.4 docs

## Context

Building the backend foundation raised several design questions the plan didn't settle, and a few cases where the plan's wording didn't match how the libraries actually behave. Each decision below was verified by an integration test, a build or a running container.

## Decisions

| Area | Decision | Why |
|---|---|---|
| Service entry points | Every business operation is `defineOperation({ name, access, input, handler })`. It authorizes the actor first, then validates the input with Zod, then runs. All operations are registered by name. | One place enforces "authorize at service level" (doc/08). Authorizing before validating means a refused caller learns nothing about the input. The registry lets the RBAC test call all 31 operations with all 7 roles. |
| Layering | Feature services may query the database directly. Complex SQL lives in dedicated modules (for example `catalog/derived.ts`). A separate `repository.ts` is used only when it removes duplication. | A repository wrapper around every query added boilerplate without adding safety. ESLint still enforces the boundaries that matter: routes and UI never touch the database, and features only use each other's public index. |
| Auth | Better Auth 1.7 with plural snake_case tables generated by the official CLI (`npx auth@1.7.9 generate`). A post-processing step converts timestamps to `timestamptz`. UUID IDs. Phone OTP is limited to Indian mobiles. Rate limits are stored in the database. | The CLI is the supported path. `timestamptz` keeps instants correct across time zones. OTP SMS goes through Indian DLT senders. Database rate limits work across replicas. |
| Staff 2FA | Enforced by `authorize()`: any staff permission needs `twoFactorEnabled`. Better Auth rotates the session when TOTP is verified. | Tested end to end: refused before enrolment, allowed after, and the next sign-in stops at the second factor. |
| OTP delivery | Sent synchronously, not through the job queue. The fake provider keeps codes in memory and the dev log, and is refused in production by env validation. | The customer is waiting for the code. |
| Email | Templates are plain React components with inline styles, rendered with `react-dom/server` **in the worker only**. React Email is not used. | All `@react-email/*` packages are now deprecated by npm, and `react-email` 6 is a heavy preview server. Next.js forbids `react-dom/server` in App Router code, so the web process only queues emails (`templates.ts`), and the worker renders and sends them (`render.tsx`, `delivery.ts`). |
| Cache invalidation | The internal endpoint calls `revalidateTag(tag, { expire: 0 })`, so the next request rebuilds. | Admin and CMS edits are rare and must be visible immediately. The default `"max"` profile would serve stale content once. |
| Job queues | Each queue's policy is in code (`QUEUE_POLICIES`). `catalog.refresh-auto-collections` uses pg-boss's `stately` policy (at most one queued and one running). | A burst of catalogue edits (the seed made about 1,000) collapses into one rebuild. A policy can't be changed after a queue is created: `ensureQueues` warns, and never deletes jobs itself. |
| Media | Local storage at `MEDIA_ROOT/{key}/{orig,320,…,1920}.webp`, with a 32-hex content-hash key. Files are written atomically by renaming a staging directory. A Next route serves `/media/*` in development (Caddy in production). `MEDIA_ROOT` must be absolute in production. | Deterministic URLs for the image loader, deduplication of identical uploads, and no half-written files. Next's standalone server changes directory on start, so relative paths break. |
| Catalogue model | Global attributes with values: `color` and `size` are variant axes, and fit, sleeve and pattern are descriptive. Category paths are `ltree` labels made of compact IDs. MRP is stored as `mrp_paise`, never below the price (database check). | Cross-catalogue filtering by colour or size. Renaming a slug never rewrites the tree. "MRP" is the legal term (Legal Metrology). |
| Collection rules | Stored as Zod-validated JSONB on `collections`, not in a `collection_rules` table. Rule-based membership is materialised in `collection_products` (`source = 'rule'`). | Rules are always read and written together. Listings use one query path for manual and automatic collections. |
| CMS | Revisions keep typed JSON plus foreign-key reference rows. Phase 1 has drafts and publishing. Review, scheduling and the editor arrive in Phase 6. Storefront reads go through `"use cache"` wrappers in `cms/queries.ts`. | Publishing works end to end now for the homepage and pages the storefront needs in Phase 2. |
| Seed | Deterministic (seeded PRNG): 65 products, 736 variants, 179 images rendered from text-free SVG silhouettes, 9 collections, CMS pages, and one account per role. Refuses to run in staging or production, or twice. | Realistic data without proprietary imagery or font dependencies. Revalidation is suppressed during the bulk load. |
| Tests | Integration tests build a fresh `duis_test` database per run (apply `02-database.sql`, run the migrations, install the queues). Media files go to a temporary directory. | Proves migrations apply to an empty database (an exit criterion) and isolates tests from development data. |

## Consequences

- The web process can never import the email renderer. Keep rendering code out of `src/server/notifications/templates.ts`.
- Changing a queue's policy in production needs a short manual step (drain, then delete the queue). The worker prints instructions.
- `doc/05` and `doc/04` are updated to match: `mrp_paise`, JSONB collection rules, the notifications split, `src/cli`, `src/db/seed`.
